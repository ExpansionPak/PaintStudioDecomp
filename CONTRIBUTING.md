# Contributing

Want to contribute to the project? Here's what you can do.

## 1. Matching functions

There are a few ways you can do this

1. **Using objdiff or first_diff.py**: Follow the build steps in README.md and **do not** modify anything before building the decomp. Once the build process has completed and it shows `build/dmpj.d64: OK`, make a new folder in the project root called `expected` and then copy-and-paste the `build` folder into the newly made folder. After this you can then open a **C** source file (e.g, `gameboot.c`), and then scroll down until you find a line of code that says something like this

```c
#pragma GLOBAL_ASM("asm/nonmatchings/gameboot/func_80002788.s")
```

Right now the code is currently using the disassembly of the function that is generated by splat into the `NON_MATCHINGS`. You can then replace this part with the equivalent **C** code you have written. Once the function has been rewritten into C, open up your terminal, and run `make clean && make` in the project root. Chances that the `MD5` hash of the newly built rom is not matching. If that happens, you can use `objdiff` or use the `first_diff.py` provided in the `tools` folder by running

```bash
python3 tools/first_diff.py
```

From there you can begin troubleshooting what your equivalent **C** code gets wrong and how you can rewrite it to match perfectly! Once your rewritten **C** code is fully-matching, you should get `build/dmpj.d64: OK`.

2. **Match existing [decomp.me](https://decomp.me/) scratches**: Go to [this preset link](https://decomp.me/preset/230) and change the "Sort by" filter to "Least matched", and find a scratch that isn't `100%` matching. If a scratch is not fully-matching but has a purple `100%` next to it, it means the scratch has already been matched by someone else.
